Judul Proyek: Bedah Topologi Docker dan Budgeting RAM — Menjalankan 5 Layanan RAG di VPS 4 GB Tanpa Out of Memory (Bagian 2 dari 10 Seri Masterclass Arsitektur RAG).

Pendekatan Materi: Memadukan Analogi Kapasitas Listrik Rumah (Sekring Jepret saat Menyalakan AC & Oven Bersamaan) dan Analogi Kost-kostan 5 Kamar dengan bedah OOM Killer Linux (Exit Code 137), kompilasi Next.js Standalone, parameter memori internal PostgreSQL pgvector, serta kebijakan eviksi Redis.

Tujuan Komunikasi: Menarik perhatian penonton dengan membongkar kesalahan paling fatal developer saat membangun sistem RAG di VPS 4 GB RAM, yaitu memaksakan model embedding lokal berjalan satu atap dengan database vektor hingga memicu OOM Killer.

Spesifikasi Visual: Bagian atas menampilkan layar terminal htop di VPS 4 GB RAM yang mendadak merah menyala (RAM 3.98/4.00 GB) diikuti pesan horor `Killed (Exit Code 137)` pada kontainer PostgreSQL. Bagian bawah menampilkan penyebabnya lewat analogi sekring rumah jepret: model embedding lokal BAAI/bge-m3 merampas 2,2 GB RAM sendirian di saat PostgreSQL sedang butuh memori besar untuk merakit grafik indeks vektor HNSW, sehingga kernel Linux terpaksa menembak mati database.

Teks Layar (Hook): "Bikin Sistem RAG di VPS 4 GB RAM Tapi Database Mati Terus (Exit Code 137)? Ini Biang Keroknya!"
